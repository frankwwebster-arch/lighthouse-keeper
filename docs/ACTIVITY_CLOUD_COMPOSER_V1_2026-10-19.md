# Activity Cloud Composer V1

**Status:** immutable, reversible review tool built 19 October 2026; not
approved, promoted, deployed or connected to runtime recipes.

## Outcome

Activity Cloud Composer V1 turns the V3 callout vocabulary into a user-authored
recipe system. Frank can name an activity, label the household asset to which it
applies, select and reorder four or five illustrated elements, and preview the
same package simultaneously as an open radial cloud and a tighter bubble/bustle.

The tool preserves the core separation rule. The household object, Prime body,
callout elements and proposed SFX are metadata-linked but remain independent
assets. Nothing contextual is baked into the Keeper.

## BBQ expansion

Five new isolated components extend the 68-item V3 menu:

- sausages;
- hot dogs;
- burgers;
- ketchup;
- charcoal and briquettes.

The default example packages all five against `outdoor.bbq`, labelled “Garden
barbecue”. The source sheet retains genuine transparency, a completely empty
sixth cell and zero-alpha declared ownership boundaries. Every derived 256 × 256
component has one owner, no shared-edge alpha and at least 16 transparent pixels
on every side.

## Composer contract

An export is valid only when it has:

- an activity label and stable recipe key;
- a household-asset label and stable asset ID;
- four or five ordered component keys and their full SHA-256 hashes;
- an explicit body-compatibility class;
- the shared 42-frame, 8 fps timing with a five-frame quiet tail;
- both `orbit` and `bustle` treatments;
- optional notes and named SFX declarations.

The browser canonicalises this metadata and displays a deterministic recipe
SHA-256. Drafts persist only in local storage unless copied or exported as JSON.
JSON can be imported again without modifying any source component.

The tool opens on callout frame 19, where all selected elements are visible in
both treatments. This is a review-interface default only: Play and frame
stepping still expose the complete 42-frame sequence and five-frame quiet tail.

If `dedicated-pose-required` is selected, both clouds remain visible but the
generic rear-work body is withheld. This prevents a useful icon recipe from
being mistaken for a validated body animation.

## Generalisation

The model is deliberately activity-neutral. Painting a picture, servicing an
appliance, gardening or any later household action can use the same contract:
add isolated vocabulary tokens through a separately reviewed source pack, then
compose them around a labelled household asset without redrawing the Keeper or
the object. A future runtime importer remains a separate approval gate.

## Files and verification

- Review tool: `public/keeper-review/activity-cloud-composer-v1/index.html`
- Draft/source/evidence: `art/drafts/activity-cloud-composer-2026-10-19-v1/`
- Builder: `scripts/build_activity_cloud_composer_v1.py`
- Verifier: `scripts/verify_activity_cloud_composer_v1.mjs`

Run:

```sh
npm run verify:activity-cloud-composer-v1
```

The verifier pins V3 inheritance, all five new source cells and component
hashes, deterministic ownership, cell gutters, tool features, review-page
syntax and the non-promotion boundary.

The browser interaction check additionally covers image preloading, the
four/five-element validity gates, the five-element selection cap, reordering,
family filtering, dedicated-pose body withholding, JSON import and local draft
persistence. The committed review media is content-addressed in
`review-archive/sets/activity-cloud-composer-v1.json`; no PNG remains in the
public review directory.
