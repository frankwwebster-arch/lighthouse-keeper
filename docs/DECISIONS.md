- Standalone Vite + React + TypeScript app; engine is pure and seeded, so every behaviour is testable.

- Chat questions follow the real clock (weekday afternoon asks about school, Saturday morning about football).
- Day is 07:00 to 21:30 game time, 8 real minutes. Bed from 19:00, annoyance from 20:00, forced to bed 21:30.
- Score out of 100 (mood 30, ship 20, friends 10, pet 10, house 10, brain 10, bedtime 10). Next day's allowance is 10 + 30% of the score. Up to 40 credits carry over.
- Camera: whole tower at rest; zooms to the object while used (not on the loo walk).
- Saves to the browser (localStorage) every 4 seconds and at day end.

Tomorrow's allowance = guaranteed base + bonus x (greens / 7). One neglected need only costs one seventh of the bonus. The 100-point score stays as a fun rating with bonus marks.
- Grown-ups panel (Menu, then Grown-ups, PIN starts as 1234): dials for the base allowance, all-green bonus, green line, first-day credits, carry-over cap, price scale and per-food prices, plus gifting credits. - Mission dials follow the price pattern: one overall setting first (mission size %, reward), then optional per-goal and per-mission numbers that win. Progress is stored uncapped so raising a target loses nothing; lowering one below what he has done finishes the mission at once.
- Missions are all open at once and count in parallel, so floors arrive in whichever order he finishes them; a mission may wait for a taller tower (`needsFloors`). A finished floor is built overnight and appears the next morning (one a morning, queued in `arriving`); the lift goes in at once. The middle-stack order lives in the save (`middle`): a new floor takes a seeded random place once and keeps it. Old saves that had extra floors above the bedroom are re-stacked with the bedroom back on top.
- Upgrades are tiers on existing objects, bought from the object's own tap menu (no furniture shop). A tier's effect is the same for every object (more good, less time; numbers in `GAME.upgrades`); the bed's tier also sets the morning's energy at 80/90/100% as in the art brief, so tier 1 now wakes at 80 rather than the old 92. Buying a tier replaces a broken object. Prices follow the dial pattern: one overall % first, then a price per tier that wins. Grown-ups can gift the next tier for free.
- Every upgrade must provide a clear, measurable gameplay benefit, such as greater effect, shorter duration, higher capacity, better reliability, a useful new action or access to new content. A visual improvement may accompany that benefit but is never sufficient by itself. If an object has no worthwhile mechanical improvement, it remains single-tier rather than receiving a cosmetic-only upgrade.
- The upgrade list is a CSV (`data/upgrades.csv`), one row per object per tier, so Frank and Codex can work from a plain table. The game uses only object, tier, name and price; perks are design notes until coded. Frank edits in a claude.ai tracker page; Claude syncs page and CSV both ways on request (Frank owns names, prices, perks and notes; Codex owns the art-status columns).
